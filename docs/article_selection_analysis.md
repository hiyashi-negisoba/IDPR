# 조문 선정: 검색 대신 모델 — 실측과 권고

2026-08-01, 잡 217520. 승인 계획서는 `~/.claude/plans/gentle-zooming-twilight.md`.
직전 단계는 `docs/phase2_handoff.md`.

## 왜 바꿨나

계획서 §검색은 dense + BM25 + 크로스인코더로 51조문 중 18개를 뽑는다. 그 설정을 뜯어보니
세 가지가 동시에 사실이었다.

1. **결정 입도에서 리랭킹을 하지 않는다.** 리랭커는 `(질의, 카드명제)` 쌍을 채점하고,
   조문 점수는 `소속 카드 최고점`의 max로 정해진다([retrieval/\_\_init\_\_.py:275-278](../src/idpr/retrieval/__init__.py#L275-L278)).
   카드가 200장인 조문은 200번 추첨하고 5장인 조문은 5번 추첨한다.
   실측: `상관(log 카드수, 비골드 선택횟수) r = 0.656`, art250(200장)은 31문항 중 28문항에
   진입해 그중 23문항이 비골드였다.
2. **세 신호 중 어느 것도 사실→쟁점 매핑을 학습하지 않았다.** 사실관계의
   "가슴과 음부를 스스로 만지게 하였다"와 카드의 "피해자를 도구로 삼아 …추행행위를 한 경우"를
   잇는 것은 유사도가 아니라 포섭이다. 학습시킬 데이터도 없다.
3. **코퍼스가 51조문뿐이라 애초에 필터가 필요 없다.** 조문번호 + 죄명 전량이 **575 토큰**이다.
   18/51을 고르는 35% 필터를 위해 인코더 두 개와 리랭커 하나를 돌리고 리콜 천장 0.848을
   감수하고 있었다.

그래서 검색을 조문 결정 경로에서 빼고, 51조문 카탈로그 전량을 모델에 주고 고르게 했다
(콜 1.5). 리콜 천장이 1.0이 된다.

채점 가능 31문항, 루브릭 골드(`data/eval/rubric_crime_article_map.json`).
모든 경로에 준용조문 결정론적 확장(제254·300·342조)을 동일하게 적용했다.

|---|---:|---:|---:|---:|---:|
| **LLM 선정** | **0.727** | 14/31 | **4.5** | **112** | **8,105** |

콜 1.5 자체 비용: 61문항 139,777 토큰 = **문항당 2,291 토큰**, 실패 0건.

### 동성능 지점의 토큰 절감

LLM 선정의 0.727을 검색이 처음 따라잡는 지점은 **top-13(0.750)**이다. 같은 성능에서:

```
콜 2 입력 토큰   46,967  →   8,105   (-82.7%)
콜 2 카드 장수      606  →     112   (-81.5%)
후보 조문         14.9개 →   4.5개   (-70%)
```

콜 1.5 비용 2.3k를 빼도 순절감 36.6k다. **조문당 효율은 검색의 3배 이상**이다 —
같은 4.5조문에서 검색은 0.402, 모델은 0.727이다.

### 그러나 리콜 최대치는 검색이 높다

검색은 k를 올려 0.911까지 간다. LLM은 4.5조문에서 멈춘다(고르라면 24개까지 고를 수 있게
스키마가 허용되어 있는데도 그렇다). **총 리콜만 보면 LLM이 진다: 0.727 vs 0.877 (top-18).**

## LLM이 놓치는 것 — 검색과 다른 것을 놓친다

LLM이 놓친 골드 34건 중 **23건이 검색 top-18 안에 있었고**, 둘 다 놓친 것은 11건뿐이다.
두 경로의 실패가 겹치지 않는다.

미회수 패턴은 명확하다. 모델은 **사건의 지배적 죄명을 잡고 인접 조문을 흘린다.**
스모크 케이스가 전형이다 (골드 art297·298·300·301·319):

```
고름: art297 강간, art300 강간등의 미수범, art319 주거침입   ← 3/5
놓침: art298 강제추행, art301 강간등 상해·치상
```

제298조는 계획서 검증 #5가 지목한 간접정범 추행, 제301조는 결합범이다. 둘 다 제297조의
**옆 조문**이고, 모델은 강간을 잡은 뒤 그 계열을 훑지 않았다. 검색은 카드 명제가 그 죄명을
직접 말하므로 잡았다.

그래서 합집합이 두 경로 모두를 이긴다:

| 경로 | 리콜 | 전량회수 | 콜2 토큰 중위 |
|---|---:|---:|---:|
| LLM 단독 | 0.727 | 14/31 | 8,105 |
| 검색 top-18 단독 | 0.877 | 19/31 | 61,986 |
| **LLM ∪ 검색 top-18** | **0.927** | **22/31** | 61,986 |
| LLM ∪ 검색 top-24 | 0.947 | 23/31 | 77,885 |
| LLM ∪ 검색 top-12 | 0.806 | 18/31 | 46,874 |
| LLM ∪ 검색 top-8 | 0.779 | 16/31 | 31,758 |

**top-18에서 합집합은 토큰을 한 푼도 더 쓰지 않는다** — 중위 문항에서 LLM의 선택이 이미
top-18 안에 포함되기 때문이다. 리콜 +0.050이 공짜다.

## 권고

### 지금 (데드라인 8/11)

**`LLM ∪ 검색 top-18` + 준용 확장 = 0.927을 채택한다.** 근거:

- 계획서 검증 #5가 "이 수치가 낮으면 하류 작업을 진행하지 않는다"고 못 박았고, 리콜은
  하류에서 회복되지 않는다. 심볼릭 게이트는 침묵에 대해 **성립하는 쪽으로 실패**하므로
  안 본 조문은 아무것도 반증하지 못한다.
- 검색 단독 대비 토큰 증가가 0이다.

토큰을 줄여야 하면 `context` 카드 261장(전체의 16%)을 콜 2에서 빼는 것이 먼저다 —
`의의·개설·보호법익·연혁`이고 **컴파일된 룰베이스의 어떤 추론 규칙도 읽지 않는다**
(`card_role ∈ {core, presumed, defeater}` 또는 `polarity == "exception"`만 읽힌다).
top-18 합집합 기준 61,986 → 51,530 토큰.

콜 2는 `max_model_len` 98,304 단일콜 또는 **조문 경계 2분할 + 65,536**이다. 후자를 권한다.
단일콜은 출력 24k 토큰에 필수 필드 819개짜리 유도 디코딩이 되고, 그것이 계획서가 별도
리스크로 적은 "일괄 판정 품질 희석"과 같은 지점이다.

### 나중 (8/11 이후)

1. **죄명 계열 확장** — 준용 확장과 같은 방식으로 제297조를 고르면 제298·299·301조를
   딸려 붙인다. LLM 미회수의 주된 패턴을 정확히 겨냥하고, 조문 구조에서 나오므로 정답
   역산이 아니다. **법률 검수 필요**(계열의 경계가 법적 판단이다).
2. **조문 집계의 크기 편향 제거** — 합집합의 검색 쪽 품질을 올린다. 규칙(예: 최고점 1장이
   아니라 상위 m장 평균)을 **논거로 먼저 확정하고 한 번만 측정**할 것. 61문항 리콜을 보며
   손잡이를 돌리면 그 수치가 검색이 아니라 적합도를 재게 된다.
3. **2-pass 재검토** — 고르지 않은 조문 목록을 다시 보여주고 "더 논할 것이 있나"를 묻는다.
   575 토큰이면 되고, 인접 조문 누락이 바로 이 형태의 실수다.
4. `stage`·`concurrence`·`participation` 카드 254장은 지금 콜 2가 판정하지만 **어떤 규칙도
   그 결과를 읽지 않는다.** 노이즈가 아니라 규칙 미작성이다 — 빼면 루브릭 죄수 항목
   140개(12%)와 미수 논점을 포기한다. 규칙을 마저 쓰는 것이 정공법이다.

## 배선 (2026-08-01 반영)

권고 두 가지를 코드에 넣었다.

**단일 진입점** — `idpr.candidates.candidate_articles()`가 모델 선정 + 검색 + 준용 확장을
합쳐 `CandidateSet`(조문, 출처 3분해, 카드)을 낸다. 출처를 합치지 않고 따로 들고 있는 이유는
"어느 축이 이 조문을 찾았나"가 두 축을 다 유지할지 결정하는 측정값이기 때문이다.

**`context` 카드 제외 — 단, 역할만으로 자르지 않는다.** 274장 중 **13장이 `exception`
polarity**이고 `element_excluded`가 polarity를 역할과 무관하게 읽는다. 역할만으로 걸렀다면
조각사유 13건이 조용히 사라졌을 것이고, 그것이 카드 무손실 불변식이 막으려는 바로 그
실패다. 조건은 `role == context AND polarity != exception` → **261장 제외, 콜 2 대상
1,697 → 1,436장.**

`tests/test_candidates.py` 9개가 둘 다 고정한다(선택 조문의 카드 무손실, exception 생존).

## 계획에서 벗어난 것

**계획서 §검색의 "검색 (LLM 0콜)"이 "선정 (LLM 1콜)"이 되고, 케이스당 3콜이 4콜이 된다.**
총 토큰은 오히려 줄어든다(콜 1.5가 2.3k, 콜 2에서 절감). 계획서는 콜 수·토큰을 병기해
공개하라고 했으므로 그대로 보고한다.

**기여 서사가 바뀐다.** 계획서 "기여의 소재"는 `issue 219항목(19%)을 검색이 결정`한다고
썼는데, 실측은 51조문 코퍼스에서 하이브리드 검색이 단독으로는 조문당 효율에서 모델에
3배 뒤진다고 말한다. 검색은 합집합의 한 축으로 남고, 조문 선정의 주역은 모델이다.
숨기지 않고 그렇게 기술한다.

`src/idpr/retrieval/`은 버리지 않는다. 합집합 경로에 쓰이고, `m2_rag` 베이스라인이며,
카드 없는 절차법 단계에서는 청크 직접 검색으로 부활한다(그때는 코퍼스가 커서 진짜 검색
문제다).
