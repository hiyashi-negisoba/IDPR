# Phase 3 upstream 검색 precision 실험 기록

## 범위와 기준선

- 실험 브랜치: `experiment/phase3-upstream-precision-20260802`
- 분기점: 동결 태그 `phase3-e2e-freeze-v1`
- 사용 문항: `kcl_criminal_r10_p1_q1_ga`,
  `CASE_KCL1730_2026_BRIBERY_FRAUD_002` 두 문항뿐이다.
- 나머지 59문항과 평가 자산은 모델 입력이나 최적화에 사용하지 않았다.
- 검색은 Call 2와 Scallop보다 앞선 article-scope 결정으로 한정했다. 검색 결과로
  구성요건 충족이나 죄책을 판정하는 로직은 만들지 않았다.

동결본의 현행 정책은 다음과 같다.

1. Call 1 FactGraph에서 모델 작성 검색어, 쟁점 라벨, 사실 파생 검색어를 만든다.
2. 각 검색어마다 BM25 문자 bigram과 `embeddinggemma-300m` 순위를 RRF(k=60)로 합치고,
   상위 100개 카드를 `bge-reranker-v2-m3`로 재정렬한다.
3. 여러 검색어에서 얻은 카드 점수는 최대값 하나로 결합한다. 한 검색어에서만 높은
   후보도 다른 검색어의 반대 신호 없이 살아남는다.
4. 카드를 issue로, issue를 article로 투영하면서 각각 최대 점수를 사용하고 article
   상위 18개를 검색 후보로 삼는다.
5. 별도 Call 1.5가 51개 전체 조문 목록에서 최대 24개를 고른다.
6. Call 1.5 조문과 검색 top-18을 문턱 없이 합집합하고 미수 조문을 결정론적으로 확장한다.
7. 선택된 각 조문에서는 전체 issue hierarchy를 복구하고 `ASSESS_ISSUE`인 쟁점을 Call 2에
   보낸다.

따라서 양쪽 중 한 경로만 조문을 지지해도 입장하며, 합집합 뒤 후보 예산이나 관련성
재검토가 없다. 동결 출력은 두 문항 모두 20개 조문이었고 KCL 71개, 사용자 문항 74개의
초기 쟁점을 만들었다.

## 실험 결과

### 1. 검색 top-k 재생

동결된 검색 순위를 prefix로 잘라 기존 후보 생성기를 그대로 재생했다.

- 사용자 문항은 검색 2위에서 `art347·355`가, Call 1.5에서 `art133`이 확보되어
  3개 조문/16개 초기 쟁점으로 핵심 3개를 모두 보존했다.
- KCL은 `art298` 5위, `art319` 7위, `art297` 9위, `art301` 10위에 있어 top-10이 되어야
  확인된 핵심 `art297·298·300·301·319`를 모두 보존했다.
- 전역 top-10 합집합은 사용자 문항 11개/45쟁점, KCL 15개/56쟁점이다.

문항마다 필요한 깊이가 다르므로 top-2 같은 값은 사용자 문항에 대한 과적합이다. top-10은
두 문항에서 확인된 핵심을 보존한 가장 단순한 공통 후보일 뿐, 두 문항만으로 일반 성능이
입증된 값은 아니다.

### 2. 검색어 간 반복 지지

Slurm `218252`에서 26개 검색어를 각각 검색하고 RRF 및 top-10 지지 횟수로 다시 합쳤다.
이 방식은 채택하지 않는다.

- KCL에서 무관한 `art250`은 17개 검색어 중 16개 top-10에 들어 1위가 됐다.
- 핵심 `art300`은 결합법에 따라 18위 또는 40위까지 밀렸다.
- 사용자 문항에서도 무관한 `art350·129`가 핵심과 같은 8회 지지를 받았다.

검색어들이 같은 FactGraph에서 파생되어 상관되어 있으므로 반복 횟수는 독립 증거가
아니었다.

### 3. LLM 후보 조율

후보 조율은 사건문, 설문, 합집합 후보, 검색된 issue·법리만 받고 루브릭·gold를 받지
않는다. 출력 enum도 현재 후보로 닫았다.

- 선택형(`218250`)은 사용자 문항에서 `art355`를 누락했고, KCL에서 `art298·319`를
  누락하면서 준강도·강도상해를 남겼다.
- precision 선택형은 사용자 문항을 정확히 3개/16쟁점으로 만들었지만 KCL 실패는 같았다.
- 모든 후보에 keep/drop을 강제한 결정행렬(`218256`)은 KCL의 `art319`를 복구했지만
  `art298`과 사용자 문항의 `art355`를 누락했다.
- 기존 Call 1 가설까지 연결한 결정행렬(`218258`)은 사용자 문항의 핵심 3개를 보존하고
  KCL을 7개/18쟁점으로 줄였지만, KCL의 `art298`을 계속 누락하고 무관한 `art337`을
  남겼다.

복수 사실 에피소드가 있는 KCL에서 같은 모델이 특정 에피소드를 반복적으로 무시했고,
후보 전체를 재판정하는 LLM gate는 recall 안전망으로 쓸 수 없었다. 사건별 예시나 특별
규칙을 프롬프트에 추가하는 미세조정은 중단했다.

### 4. 구성요건 issue만으로 조문 입장 순위 산정

Slurm `218261`에서 support·concurrence·stage issue가 article을 입장시키지 못하도록 하고
element issue만 검색했다. 조문이 입장한 뒤에는 기존 전체 hierarchy를 그대로 복구했다.

그럼에도 top-18에서 사용자 문항 19개/80쟁점, KCL 21개/74쟁점으로 오히려 악화됐다.
KCL 핵심의 최심 순위가 10위에서 9위로 한 칸 당겨진 것 외에 precision 이득이 없어서
채택하지 않는다.

### 5. 현행 검색 top-10 downstream E2E

Slurm `218265`에서 동결 Call 1/1.5를 그대로 복사하고 top-10 L0만 사용하여
`Call 2 → Scallop → Call 3`을 캐시 없이 다시 실행했다. 계약 검증은 통과했다.

| 문항 | 지표 | 동결 top-18 | top-10 | 변화 |
|---|---:|---:|---:|---:|
| KCL | 조문 / 초기 쟁점 | 20 / 71 | 15 / 56 | -5 / -15 |
| KCL | Call 2+3 토큰 | 78,013 | 65,718 | -15.8% |
| 사용자 문항 | 조문 / 초기 쟁점 | 20 / 74 | 11 / 45 | -9 / -29 |
| 사용자 문항 | Call 2+3 토큰 | 98,621 | 59,619 | -39.5% |
| 합계 | Call 2+3 토큰 | 176,634 | 125,337 | -29.0% |

KCL은 동결본과 마찬가지로 Scallop `final_offense`에 확인된 핵심
`art297·298·301·319`가 모두 남았다. 그러나 잘못 확정된 `art334·337`도 그대로여서
검색 top-k 축소가 downstream 법률판단 오류를 고치지는 못했다. 답안은 강제추행,
주거침입, 강간미수, 강간등치상을 계속 서술하지만 위요지·공동주택 법리 부족과 일부
섹션 결론 오결박도 그대로다. 이는 추가 검색이 아니라 rulebase/Call 2/Call 3 문제다.

사용자 문항은 동결본의 `final_offense={art347, art360}`에서
`{art133, art329, art347, art355, art360}`으로 바뀌었다. 확인된 핵심 `art133·347·355`가
모두 Scallop과 답안에 반영된 점은 개선이다. 반면 절도 `art329`와 점유이탈물횡령
`art360`도 잘못 확정되고, Call 3에는 수뢰·친족상도례·권리행사방해·문서죄까지 남아
precision 문제는 해결되지 않았다.

E2E manifest는
`experiments/results/phase3_top10_e2e/e2e_manifest.json`이며, 생성에 사용된 코드 SHA는
`6db53c5`, Slurm job은 `218265`다.

## 현재 판단

- 검색어 점수 결합, issue-function 필터, LLM gate 중 어느 것도 두 문항에서 recall과
  precision을 함께 안정적으로 개선하지 못했다.
- 현재 유일한 보수 후보는 기존 알고리즘을 변경하지 않은 전역 top-10이다. 두 문항에서
  확인된 핵심을 보존하고 downstream 토큰을 29.0% 줄였으며 구조 계약도 통과했다.
- 그러나 두 문항만으로 일반 recall을 보증할 수 없고, symbolic false positive와 Call 3
  잡음도 남았다. 따라서 `DEFAULT_TOP_K_ARTICLES=18`은 변경하지 않고 top-10을 실험 후보로
  보존한다. 이 시점에서 더 작은 k나 사건별 동적 k를 고르면 두 문항에 대한 과적합이다.
- 다음 검색 변경은 별도 개발 세트나 사용자 승인 범위가 생길 때 top-10을 재검증하는
  것이 맞다. 현재 두 스모크만으로는 LLM gate나 새 heuristic을 production에 넣지 않는다.
