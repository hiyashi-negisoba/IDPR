## 검색 원인 판정

### 미회수

두 문항의 in-corpus 핵심 조문은 모두 L0에 있었다.

- KCL: `art298`, `art319`, `art297`, `art300`, `art301`
- 사용자 문항: `art133`, `art347`, `art355`

`art276`, 강요·협박 조문, 성폭력 특별법 결합 죄명처럼 빠진 항목은 현재 corpus 밖이다.
후보 수나 retrieval prompt를 바꿔도 회수할 수 없다. 따라서 이 두 스모크에서 검색
리콜을 높이기 위한 변경 후보는 **없다**.

### 과다회수

검색이 실제 원인인 문제는 과다회수다.

- KCL은 핵심 5개를 포함하지만 총 20개 조문, 71개 초기 issue, 16개 답안 section이 됐다.
- 사용자 문항은 핵심 3개를 포함하지만 총 20개 조문, 74개 초기 issue, 18개 section이 됐다.
- 사용자 문항의 절도·점유이탈물횡령·문서죄·방화·강간 등은 질문과 무관하며 Call 2/3
  token과 최종 답안의 잡음을 직접 증가시켰다.

## 승인 전에 정해야 할 종료 조건

1. 핵심 조문 보존 목표(현재 두 스모크 기준 8/8보다 낮출 수 있는지)
2. 문항당 허용 최대 조문 수와 초기 issue 수
3. Call 2+3 token 상한
4. 최대 실험 횟수와 총 GPU 시간
5. 즉시 중단할 회귀 조건
6. 두 스모크에 맞춘 threshold를 일반화로 오인하지 않기 위한 과적합 방지 조건

이 조건과 구체 변경안에 대한 사용자 승인 전에는 검색 최적화를 시작하지 않는다.
